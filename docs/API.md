# API reference

Base URL in production: `https://chat-bot-ai-ouc2.onrender.com` · local: `http://127.0.0.1:8000`

Interactive docs generated by FastAPI are available at `/docs` (Swagger UI) and `/redoc`.

## Conventions

- **Authentication:** every `/api/...` endpoint except `/api/health`, `/api/channels`, `/api/public/...` and
  `/api/auth/request-code`, `/verify` and `/google` needs `Authorization: Bearer <token>`. Get a token from [`/api/auth/verify`](#post-apiauthverify)
  or [`/api/auth/google`](#post-apiauthgoogle).
- **Chat keys:** chats linked to WhatsApp/Instagram that nobody has claimed yet can be opened with
  `X-Chat-Key: <key>`. The chat list accepts `X-Chat-Keys: <chatId>:<key>,<chatId>:<key>`.
- **IDs** are MongoDB ObjectId strings (24 hex characters). **Dates** are ISO 8601 in UTC.
- **Errors** use FastAPI's format: `{"detail": "Human-readable message"}`. Validation errors (`422`) return a list in
  `detail`.

| Status | Meaning |
|---|---|
| `400` | Bad request (for example an expired or wrong sign-in code) |
| `401` | Missing, expired or invalid session token |
| `403` | Webhook signature or verify token didn't match |
| `404` | Not found, or no access (the API doesn't reveal which) |
| `422` | Invalid input (validation, unsupported file, too many files) |
| `429` | Rate limit (sign-in codes) or too many attempts |
| `502` | An upstream service failed (AI model, email provider) |
| `503` | A feature isn't configured on the server (for example Google sign-in) |

## Health and configuration

### `GET /api/health`
Liveness check. No auth.

```json
{ "status": "ok", "database": "connected", "model": "openrouter/free", "inference": "https://openrouter.ai/api/v1" }
```
`status` is `"degraded"` and `database` is `"unavailable"` when MongoDB can't be reached.

### `GET /api/channels`
Which messaging apps are connected (used by the "Continue on…" button). No auth.

```json
{
  "whatsapp":  { "enabled": true, "number": "15551470585", "url": "https://wa.me/15551470585" },
  "instagram": { "enabled": true, "username": "zenoxi.ai", "url": "https://ig.me/m/zenoxi.ai" }
}
```

## Authentication

### `POST /api/auth/request-code`
Emails a 6-digit code.

| Field | Type | Notes |
|---|---|---|
| `email` | string | Required. |
| `mode` | `"signin"` \| `"signup"` | `signin` fails with `404` if there's no account; `signup` fails with `409` if there is. |
| `name` | string | Required for `signup`, max 60 characters. |

**Response `200`:** `{ "sent": true, "email": "asha@example.com", "resend_after": 60 }`

**Errors:** `404` no account · `409` account exists · `422` invalid email or missing name · `429` resend within 60 s or
more than 6 codes an hour · `502` email provider failed.

### `POST /api/auth/verify`
```json
{ "email": "asha@example.com", "code": "482915" }
```
**Response `200`:**
```json
{ "token": "5mI2…", "user": { "id": "6af3…", "email": "asha@example.com", "name": "Asha", "picture": null } }
```
**Errors:** `400` wrong or expired code (the message says how many tries are left) · `429` five wrong attempts.

### `POST /api/auth/google`
```json
{ "credential": "<Google ID token from Google Identity Services>" }
```
Signs in or signs up. An existing account with the same verified email is reused.
**Response:** same as `/verify`. **Errors:** `401` invalid token or unverified email · `503` `GOOGLE_CLIENT_ID` not set.

### `GET /api/auth/me`
**Response `200`:** the user object (`id`, `email`, `name`, `picture`).

### `POST /api/auth/logout`
Deletes the current session. **Response `200`:** `{ "ok": true }`

## Chats

### `GET /api/chats`
The user's chats, newest first (max 200), plus unclaimed linked chats whose keys are sent in `X-Chat-Keys`.

```json
[
  { "id": "6af3…", "title": "Plan a 3 day trip to Goa", "channels": ["instagram"], "private": true,
    "created_at": "2026-11-11T17:02:11+00:00", "updated_at": "2026-11-11T17:05:40+00:00" }
]
```
`channels` lists the messaging apps linked to the chat. `private` is `true` once the chat has an access key.

### `POST /api/chats`
`{ "title": "New chat" }` (optional, max 100 characters) → the new chat object.

### `GET /api/chats/{chat_id}`
One chat object.

### `DELETE /api/chats/{chat_id}`
Deletes the chat, its messages, documents, messaging links and pending link codes.
**Response:** `{ "deleted": true }`

### `GET /api/chats/{chat_id}/messages`
Up to 500 messages, oldest first.

```json
[
  { "id": "…", "chat_id": "…", "role": "user", "content": "Best laptops for students?", "channel": "web",
    "sources": [], "attachments": [], "created_at": "…" },
  { "id": "…", "chat_id": "…", "role": "assistant", "content": "Here are… [1]", "channel": "web",
    "sources": [ { "title": "…", "url": "https://…", "domain": "wired.com", "snippet": "…" } ],
    "attachments": [], "created_at": "…" }
]
```

### `POST /api/chats/{chat_id}/messages`
Sends a message and **streams** the reply as newline-delimited JSON (`application/x-ndjson`).

| Field | Type | Notes |
|---|---|---|
| `content` | string | Required, 1 to 12,000 characters. |
| `web_search` | boolean | Default `false`. |
| `attachment_ids` | string[] | IDs of this chat's documents to show on the message (max 10). All of the chat's documents are used as context either way. |

**Stream events**, one JSON object per line:

| Event | Example | When |
|---|---|---|
| `status` | `{"type":"status","stage":"searching"}` | Web search started |
| `sources` | `{"type":"sources","sources":[{"title","url","domain","snippet"}]}` | Search results found |
| `notice` | `{"type":"notice","message":"Web search is unavailable…"}` | Search failed; the answer continues without it |
| `token` | `{"type":"token","content":"Hel"}` | A piece of the answer |
| `done` | `{"type":"done","message_id":"6af3…"}` | Answer saved |
| `error` | `{"type":"error","message":"OpenRouter's free usage limit was reached…"}` | The model request failed |

**Example (curl):**
```bash
curl -N -X POST "$API/api/chats/$CHAT/messages" \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"content":"What is new in Python 3.15?","web_search":true}'
```

### `POST /api/chats/{chat_id}/link-code`
Creates a one-time code to continue this chat on WhatsApp or Instagram. Makes the chat private if it wasn't already.

```json
{
  "code": "KX7M2Q", "expires_at": "2026-11-11T17:20:00+00:00", "key": "<chat access key>",
  "whatsapp":  { "enabled": true, "number": "15551470585", "url": "https://wa.me/15551470585?text=link%20KX7M2Q" },
  "instagram": { "enabled": true, "username": "zenoxi.ai", "url": "https://ig.me/m/zenoxi.ai" }
}
```

## Documents

### `POST /api/chats/{chat_id}/documents`
`multipart/form-data` with one `file` field. Supported: `.pdf`, `.docx`, `.txt`, `.md`, `.csv`, `.tsv`, `.json` and
common code/text formats. Max 10 MB, 10 files per chat.

**Response `200`:**
```json
{ "id": "…", "filename": "handbook.pdf", "kind": "pdf", "size": 27104, "pages": 9, "chars": 37872, "created_at": "…" }
```
**Errors (`422`):** unsupported type · empty file · over 10 MB · scanned PDF with no text · password-protected PDF ·
damaged file · 10 files already attached.

### `GET /api/chats/{chat_id}/documents`
List of document objects (without the extracted text).

### `DELETE /api/chats/{chat_id}/documents/{document_id}`
**Response:** `{ "deleted": true }`

## Resume ATS Match

Resume data sent to these endpoints is not stored.

### `POST /api/resume/analyze`
`multipart/form-data`:

| Field | Notes |
|---|---|
| `job_description` | Required, 30 to 30,000 characters. |
| `file` | Resume file (PDF, DOCX, TXT, MD), **or** |
| `resume_text` | Pasted resume text (max 60,000 characters). |

**Response `200`:**
```json
{
  "resume_text": "Asha Rao\n…",
  "analysis": {
    "score": 42, "keyword_score": 32, "format_score": 71,
    "matched": ["React", "REST APIs", "Jest"],
    "missing": ["TypeScript", "Next.js", "Redux"],
    "checks": [ { "id": "email", "label": "Email address", "ok": true, "tip": "…", "detail": null } ]
  }
}
```
`score` = 75% weighted keyword coverage + 25% formatting checks. The checks are `email`, `phone`, `linkedin`,
`sections`, `length`, `bullets` and `metrics`.

### `POST /api/resume/tailor`
```json
{ "resume_text": "<from /analyze>", "job_description": "…" }
```
**Response `200`:**
```json
{
  "resume": { "name": "…", "headline": "…", "contact": { … }, "summary_title": "Summary", "summary": "…",
              "education": [ … ], "skills": [ { "group": "Frontend", "items": ["React"] } ],
              "experience": [ … ], "projects": [ … ], "activities": [ … ], "certifications": [ … ],
              "personal": [ … ], "changes": ["Renamed ReactJS to React…"], "suggestions": ["TypeScript"] },
  "text": "<plain-text version>",
  "before": { …analysis… }, "after": { …analysis… },
  "layout": { "scale": 0.88, "one_page": true }
}
```
`suggestions` lists job keywords the resume doesn't support (never added automatically).
**Errors:** `502` the AI model failed or returned unusable output twice.

### `POST /api/resume/pdf` · `POST /api/resume/docx`
Body: `{ "resume": <resume object from /tailor> }`. Returns the file as a download
(`application/pdf` or `.docx`). The PDF response also has `X-Resume-Scale` and `X-Resume-One-Page` headers.

## Website Agents (owner)

All need the owner's bearer token. An owner only sees their own agents (max 5).

| Endpoint | Purpose |
|---|---|
| `GET /api/agents` | The owner's agents, each with `stats` (`leads`, `messages_today`). |
| `POST /api/agents` | `{ "business_name": "…", "website": "optional.com" }`. Reads the website (if given), allows its domain, and starts the interview. |
| `GET /api/agents/{id}` | One agent: `public_key`, `status` (`draft`/`live`), `disabled`, `profile`, `settings`, `allowed_domains`, `interview`. |
| `PATCH /api/agents/{id}` | Any of `name`, `status`, `allowed_domains[]`, `settings` (see below). Going `live` needs knowledge and at least one domain. |
| `DELETE /api/agents/{id}` | Deletes the agent and its knowledge, conversations and leads. |
| `POST /api/agents/{id}/interview` | `{ "message": "…" }` → `{ "reply", "interview" }`: the next consultant question. |
| `POST /api/agents/{id}/profile/generate` | Builds a business profile (JSON) from the interview + website. Not saved yet. |
| `PUT /api/agents/{id}/profile` | `{ "profile": {…} }` saves the reviewed profile as knowledge and fills suggested questions. |
| `GET /api/agents/{id}/sources` | Knowledge sources: `kind` (`profile`, `page`, `file`, `note`), `title`, `source`, `chars`. |
| `POST /api/agents/{id}/sources/website` | `{ "url" }`: reads up to 8 pages of a public website (private and internal addresses are refused). |
| `POST /api/agents/{id}/sources/file` | Multipart `file` (same types as chat documents). |
| `POST /api/agents/{id}/sources/text` | `{ "title", "text" }`: a free-form note. |
| `DELETE /api/agents/{id}/sources/{source_id}` | Removes a source. |
| `POST /api/agents/{id}/test` | `{ "message", "history": [] }` → NDJSON stream (`token`, `final` with `show_form`, `error`). No limits. |
| `GET /api/agents/{id}/leads` | Inquiries, newest first (max 500): `fields`, `page_url`, `consent`, `status`, `notes`, `summary`, `documents`, `conversation_id`. |
| `PATCH /api/agents/{id}/leads/{lead_id}` | `{ status: new|contacted|interested|won|lost, notes }`. |
| `DELETE /api/agents/{id}/leads/{lead_id}` | Deletes one lead. |
| `GET /api/agents/{id}/leads/export?format=xlsx|csv&status=` | Downloads leads as Excel or CSV (CSV cells starting with `= + - @` are escaped). |
| `GET /api/agents/{id}/conversations/{conversation_id}` | The visitor chat behind a lead. |
| `PATCH /api/agents/{id}/sources/{source_id}` | `{ shareable }`: lets visitors request this file (brochure) by email. Only uploaded files (≤ 5 MB) can be shared. |
| `POST` / `DELETE /api/agents/{id}/avatar` | Uploads (PNG/JPEG/WebP, resized to 256 px) or removes the agent's logo. |
| `PUT` / `DELETE /api/agents/{id}/ai-key` | `{ key: "sk-or-…" }`: the owner's own OpenRouter key (stored encrypted; only the last 4 characters are returned). |
| `GET /api/agents/{id}/analytics` | 14-day series, totals (`messages`, `leads`, `conversion`, `answered_free`, `saved_percent`), leads by status, top questions. |
| `GET /api/agents/{id}/unanswered` | Questions the agent couldn't answer. `POST …/unanswered/{item}/answer` `{ answer, as_faq }` teaches it; `DELETE` dismisses. |
| `GET /api/agents/{id}/emails` | Email log: `kind`, `to`, `subject`, `status` (`sent`/`logged`/`failed`/`skipped`), `error`. |
| `POST /api/agents/{id}/report/send` | Sends the leads report to the owner now. |

**Avatar, language and emails** in `settings`: `avatar` `{ type: orb|initials|emoji|image, emoji }`, `language`
(`en`/`hi`/`te`/`ta`), and `emails` `{ notify_owner, owner_email, visitor_confirmation, confirmation_subject,
confirmation_body, send_documents, followup: { enabled, days, subject, body }, report: off|daily|weekly }`.
Templates can use `{name}`, `{business}` and any form field key.

**`settings` object:** `welcome_message`, `color` (`#rrggbb`), `position` (`left`/`right`), `tone`, `suggested_questions[]`
(max 4), `handoff_message`, and `form`: `{ enabled, style: "card"|"chat", title, button_label, success_message,
fields: [{ key, label, type: text|email|phone|select|date|textarea, required, options[] }] }` (max 10 fields).

## Website Agents (public widget API)

Called by `widget.js` on the owner's website. No login. CORS is open on `/api/public/*`; instead each request's
`Origin` must be one of the agent's `allowed_domains` (or a subdomain), or Zenoxi's own site (preview, works while in
draft). Requests without an `Origin` are refused.

| Endpoint | Purpose |
|---|---|
| `GET /api/public/agents/{public_key}/config` | Widget settings: `name`, `business_name`, `welcome_message`, `color`, `position`, `suggested_questions`, `form`, `preview`. |
| `POST /api/public/agents/{public_key}/chat` | `{ visitor_id, conversation_id?, message, page_url? }` → NDJSON stream: `conversation` (id), `token`…, `final` `{content, show_form}` or `error`. |
| `GET /api/public/agents/{public_key}/avatar` | The agent's logo (PNG, cached). |
| `GET /api/public/unsubscribe?l=&t=` | Signed link in emails; stops further emails to that visitor from that agent. |
| `POST /api/public/agents/{public_key}/leads` | `{ visitor_id, conversation_id?, fields: {…}, consent, documents?: [source ids], page_url?, website: "" }` → `{ ok, message }`. `422` lists invalid fields in `detail.fields`. `website` is a spam trap and must stay empty. |

**Limits:** 20 messages per 10 minutes and 5 inquiries per hour per visitor IP, per agent; `AGENT_DAILY_MESSAGES`
(default 100) messages per agent per day (`429` when exceeded). Disabled or non-live agents return `403`.

## Scheduled jobs

`POST /api/cron/run` with header `X-Cron-Secret: <CRON_SECRET>` runs due lead reports and follow-up emails. Optional:
the server already runs them every 30 minutes when `BACKGROUND_JOBS=true`.

## Admin

Only for users whose email is in `ADMIN_EMAILS`; everyone else gets `403`. `GET /api/auth/me` includes `is_admin`.
You can't block or delete your own account or another admin.

| Endpoint | Purpose |
|---|---|
| `GET /api/admin/overview` | Users (total, new and signed in today, blocked), chats, agents, leads, visitor messages, free answers, failed emails today, and a 14-day `series`. |
| `GET /api/admin/users?q=&skip=` | 50 users at a time (search by name or email): chats, agents, last sign-in, `blocked`, `is_admin`. |
| `GET /api/admin/users/{id}` | One user: message, document and session counts, recent chats, agents. |
| `POST /api/admin/users/{id}/block` | `{ "blocked": true|false }`. Blocking signs them out, refuses sign-in (`403`) and pauses their agents; unblocking restarts only the agents the block paused. |
| `DELETE /api/admin/users/{id}` | Deletes the account with its chats, messages, documents, agents, leads and sessions (for deletion requests). |
| `GET /api/admin/agents?q=&status=live|draft|disabled` | Every agent with owner, domains, messages today and over 7 days, free answers, emails today, leads, own-key flag. |
| `POST /api/admin/agents/{id}/status` | `{ "disabled": true|false }`: disabled agents stop working everywhere. |
| `GET /api/admin/emails?status=sent|logged|failed|skipped` | The latest 200 agent emails, with errors. |
| `GET /api/admin/system` | Which services are configured (never their values), last scheduled-job run, limits, admin emails. |
| `POST /api/admin/jobs/run` | Runs due reports and follow-ups now. |

## Messaging webhooks (called by Meta)

| Endpoint | Purpose |
|---|---|
| `GET /webhooks/whatsapp`, `GET /webhooks/instagram` | Verification handshake. Returns `hub.challenge` as plain text when `hub.verify_token` matches `META_VERIFY_TOKEN`; otherwise `403`. |
| `POST /webhooks/whatsapp` | WhatsApp Cloud API events. Requires a valid `X-Hub-Signature-256` (HMAC-SHA256 of the body with `META_APP_SECRET`). |
| `POST /webhooks/instagram` | Instagram messaging events. The signature may use `INSTAGRAM_APP_SECRET` or `META_APP_SECRET`. |

POST webhooks answer `{"ok": true}` right away and process messages in the background. Duplicate deliveries are
ignored by message ID.

### Commands users can send on WhatsApp/Instagram

| Command | Effect |
|---|---|
| `link CODE` | Continue the website chat that produced `CODE` |
| `/web` | Reply with a private link to open this chat on the website |
| `/new` | Start a new chat |
| `/search <question>` | Answer using live web results |
| `/help` (or `hi` the first time) | Show the commands |
| *(any other text)* | Normal chat message |
| *(WhatsApp document)* | The file is read and attached to the chat; its caption is treated as a question |
